## 可重复的自动验收

```powershell
cmake --build build --config Release --parallel 4
ctest --test-dir build -C Release --output-on-failure
```

| CTest 项 | 核心覆盖 |
| --- | --- |
| `unit.combinations` | 全部 16 组合、双向伤害、格挡、能量变化 |
| `unit.rules` | 上限、非法行动、下轮大招、保留/消耗、双方同时死亡、无部分修改 |
| `unit.ai` | 合法性、固定种子、玩家当前选择不影响预选 AI、满能量分布 |
| `unit.rooms` | 六位前导零、多个房间唯一、不存在、重复加入、第三人拒绝 |
| `unit.authority` | 归属字段、重复/错误轮次、第一提交不泄漏、同一份结算、展示期禁用 |
| `unit.timeouts` | 自动防御、截止前/截止时提交、事件次序竞争只结算一次 |
| `unit.rematch` | 非零能量终局、双方同意、完整重置、不复用令牌、拒绝回收 |
| `unit.protocol` | 字段类型、整数范围、枚举、额外字段、长度编码、JSON 往返 |
| `unit.cleanup` | 断线、主动离开、等待超时、房间回收 |
| `unit.config` | 有效、缺失、格式损坏、语义无效配置 |
| `integration.real_tcp` | 真实 C++ 客户端 + Python socket + 独立服务端进程 |

## 手动验收清单

以下是可复做的操作清单，不表示全部步骤已逐项手动完成。

### 单机

- [ ] 点击 Play vs AI，初始双方 5 HP / 0 能量，右侧显示 Hidden。
- [ ] 先按 1 再按 3，确认前可修改；Enter 提交后揭晓 AI，展示期不能再提交。
- [ ] 观察双方攻击同时扣血，普通攻击被防御挡住。
- [ ] 蓄力中受伤仍加能量，普通攻击/防御保留已有能量。
- [ ] 满能量后 Charge 禁用，Ultimate 可用，下一轮释放消耗全部能量并穿透防御。
- [ ] 终局显示胜/负/平，Play again 恢复初始状态，Menu 返回主菜单。

### 双客户端本机联机

- [ ] 启动服务端及两个客户端，均连接 localhost:28765。
- [ ] 创建房间并复制编号；加入者点击编号框，Ctrl+V 或键入六位编号。
- [ ] 双方自动开局，左侧均为自己，房间号、回合号一致。
- [ ] 一方先提交，另一方只看到 Submitted / hidden，不能看到行动。
- [ ] 第二方提交后同时揭晓；双方日志应按各自视角镜像，权威生命/能量一致。
- [ ] 连续五轮都 Attack，双方归零为平局。
- [ ] 只一方请求再战时仍等待；双方同意后恢复初始状态与第 1 轮。
- [ ] 一方拒绝再战，另一方收到离开提示；展示期不能提前提交新轮行动。
- [ ] 超过 30 秒不选择，服务端自动防御；关闭一个窗口，另一方显示断线而非正常胜利。
- [ ] 返回菜单后能重新创建房间，错误地址/端口/房间编号能返回菜单重试。

### 配置与部署

- [ ] 用不同客户端规则配置连接同一个服务端，联机仍使用服务端规则。
- [ ] 修改端口后两端保持一致；从构建目录启动仍能读取旁边的配置。
- [ ] 删除配置或把 JSON/数值改坏，程序输出明确错误并非零退出。
- [ ] 两台局域网电脑使用服务端内网地址和开放端口完成对局。
- [ ] 公网环境确认地址/端口可达，不把房间号当作 NAT 穿透或加密机制。

单窗口辅助验收：先在图形客户端创建房间，再执行 `python tests/manual_peer.py 六位编号`。该脚本是测试对手，收到你的提交后固定普通攻击，不属于游戏 AI；有心跳，终局自动请求再战，Ctrl+C 停止。
